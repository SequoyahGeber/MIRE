# Playtest report — 2026-08-20

Sequoyah played the shipped procedural build and reported 35 distinct problems in one pass. This
file is the index: what he said, and which finding carries it. **The findings are the work items**
(`agent brief F-3NN`); this file exists so nobody has to reconstruct the play session to understand
why a finding exists, and so the next triage can see the whole report at once rather than 28
unrelated entries.

Two captures came with it: a daytime view over the river channel with a Crawler in the foreground
(119 FPS), and the death screen at Cycle 1 (120 FPS). Both are referenced by the findings that read
them.

## What the report actually says about the build

Framerate is fine. Every problem is content, feedback, or a system that shipped without its
consumer. Three of them are hard progression stops that make the procedural map unfinishable:

| | Why it stops the run |
|---|---|
| F-366 | `fibre_bundle` has no harvestable source, so neither starter tool can be crafted |
| F-365 | No scatter def places a rock, so `stone` and `iron_ore` have no source at all |
| F-367 | No chest reaches the island, so the one fibre fallback (a bog table) never spawns |

Together: bare hands, forever. Everything gated behind `required_tool` 1 or 2 — which is every
wood and stone node in `content/harvestables/` — is unreachable in a shipped run.

## One structural note worth keeping

Several of these are the same shape: **a system shipped and its consumer did not.** The ambient
music tracks are rendered and imported and nothing plays them (F-373). `ChestPlacementService` is
complete and no marker reaches it (F-367). `HarvestLibrary` can answer "what tool does this need"
and no UI asks (F-388). `EnvironmentVfx` has the particle vocabulary for destruction debris and
nothing fires it (F-391).

That pattern is worth a check rather than a habit: an asset or service with zero shipped callers is
mechanically detectable, and every instance of it in this report reached a player build.
